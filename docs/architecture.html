每个阶段都是一个「合约 + 门控」：模型必须输出机器可读的标记行，后端据此判定是否放行；不放行则先做进度修复、再做合约修复。

门控与降级：S2 / S3 / S4 / S5 是 hard gate；失败先做 1 次合约修复、最多 2 次进度修复。S4 仍无实弹证据时不阻塞全局，而是 DeferPhase 把 claim 保留为 needs-poc / source-backed，交给 S5 以「generated-not-verified」发布。
证据纪律：S1 只排班不下结论；S2 只出候选；S3 不调用工具；S4 每条 handoff claim 必须落到 VERIFY / REJECTED / S4_SKIP 三者之一；S5 不重新发现漏洞，只打包可复放 PoC。

4去重与家族指纹算法

目标不是文本相似，而是「同一根因 + 同一路由/sink + 同一利用原语」；不同 PoC 单元即使共享根因也保持分离。

STEP 4
选主 + 排序
组内按 severity → verification → duplicates → title 排序；保留主条目，其余记入 duplicates；全量再按同一 rank 排序并编号。

5跑批判定算法（deploy / CyberGym）

单任务 = 一次隔离容器运行 + PoC 收集 + 提交 + 阴阳两跑 + 多轮投票；超时按 stage 续跑，磁盘不足直接落账不重试。

6

vul 跑与 fix 跑；按退出码判定，多轮取多数票，平票 unstable。

判定表： vul 不崩 → no_crash； vul 崩 & fix 未跑 → vul_only； vul 崩 & fix 退出 0 → solved； vul 崩 & fix 也崩 → fix_also_crashes。 原因是 MSan 类未初始化读依赖堆布局，单次结果不可信，故 --verify-rounds 多轮取多数票，平票按「没解出」保守处理。
续跑：超时后读 stage(N-1)/runbook.json，删除 stageN 及之后目录，复用同一 run_id 从 stageN 重跑；粒度是整个 stage。

6横切机制

统一 LLM 重试

四层重试统一为「默认重试、显式排除」：除用户取消、配置/环境错误、上下文超长、需先修历史的请求外，全部重试。

delay = min(base × 2attempt-1 × rand(0.9, 1.1), max_delay)
HTTP 层默认 8 次、流/turn 层默认 10 次、GUI lane 层默认 8 次（TRILANE_LANE_MAX_ATTEMPTS 可配）；两层预算相乘，最坏约百次请求但退避封顶。

安全与隔离边界

Safe 模式默认；Lab 模式才放开本地文件系统与命令执行。沙箱按平台落地：Linux Landlock/seccomp，macOS Seatbelt，Windows sandbox；出网经网络代理与策略判定。

批处理再套一层：每任务独立 dind，智能体容器只能看到私有 dockerd；宿主 daemon 对智能体不可见；进度、日志、状态目录同路径挂载以兼容 dind 路径解析。
